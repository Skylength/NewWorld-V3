## 游玩中人物形成与长期交往 v0.1

更新：2026-11-11。状态：**已授权开发，实现与本轮自测完成，待用户试玩验收。** 本节是本次增量的需求主文档，技术方案见 [ARCHITECTURE.md](ARCHITECTURE.md#游玩中人物形成与长期交往-v01)。下文 NPC core、Director 联动及 10 月内容保留为既有能力和历史记录，不证明本增量已交付。

### P-1 目标与优先级

优先解决：玩家在游玩中用自然语言引入一个具体人物，选择是否持续关注，并通过长期交往逐渐认识和塑造同一个人。玩家无需先填写人物卡，也无需知道系统何时建档。

核心例子：“掌门，你怎么来了（女性）”。在世界尚无冲突设定时，系统能够引入一位女性掌门并开始交往；已有相应人物时复用身份。括号中的创作要求与说出口的台词分开。后续姓名、背景、性格表现、关系及约定逐步形成，跨称呼、离场、返访和重启仍然连续。

优先级：

1. P0：游玩中引入、身份连续、明确设定与经历可靠保存、实际请求使用相关资料。
2. P0：记住/取消关注、增量丰富、未完成约定、关系连续、权限及失败一致性。
3. P1：按预算维护有来源的长期摘要，改善较长交往的上下文；作为本功能后续交付步，单独验明效果。
4. 不纳入本次：开局创建与带入、人物模板库、创建表单优化。这些需求优先级远低于游玩中的人物形成，不为它们预建流程。

“实体人物”指其身份、已成立事实、共同经历和行为依据持续有效，不以人物卡填满、达到固定互动轮数或开启独立运行作为完成条件。

### P-2 范围与保留边界

本次覆盖单玩家本地世界，沿用既有时间、场景、行为能力和存档。自然引入、关注、持续资料更新、上下文加载及相应调试证据是完整范围；界面提供必要操作与结果，“记住此人”采用弹窗确认，不要求通过自然语言设置关注，不扩展其他布局或视觉方案。

- 普通人物和被记住人物使用同一身份与历史；关注只改变长期维护、检索优先级，不重新生成人物。
- 关注状态、玩家已知信息和既有独立运行状态分别维护。记住不自动启用独立行为、不增加好感、不传播秘密，也不推进世界时间。
- 普通人物仍能合理回应当前交往，保留已经发生的交易、对白及因果。取消关注不删除身份、事件、资源后果或已有活动。
- 不给群体背景、假设对象、仅被提及的未知人逐个生成完整人物；明确发生个体互动或承担具体后果时才需要稳定身份。
- 保留现有独立人物的决策权、通信和能力执行；本次不重做战斗、经济、寻路、世界时间调度或完整社会模拟。
- 不承诺任意长历史都能零误差召回。容量和预算不足时保留原始资料、说明限制，不静默丢弃关键事实或伪装为已经记住。

### P-3 行为要求

#### IC-01 自然引入与输入含义

玩家对白、动作、创作设定、假设及界外评价应区别处理。“（女性）”在此例中是创作约束，不送入人物的听闻经历；括号本身不是通用判定规则。“你是不是讨厌我”是问话，不能直接成为她讨厌玩家的事实。

玩家对未定义角色的明确引导可以建立初始内容；与已成立身份、位置或历史冲突时不能悄悄覆盖。已有异地掌门不会因被叫到称呼就自动出现。缺少某个姓名、职业等词不应使合法自然表达无法进入链路。

#### IC-02 同一人物从首次具体交往开始连续

“掌门”“她”“沈掌门”“沈清岚”在上下文明确时指向同一个人。相同职务在不同宗门可以指向不同人；同名和同地不能单独证明同一身份。身份不清时可以暂不落实含混的动作，并自然澄清，不能默认另造一个人物解决歧义。

资料稀少时也可以保留稳定身份；不得积累多轮后再用新生成的人物覆盖此前对象。姓名未公开或未确定时允许保持称呼，不能仅为填表而强制生成真名。

#### IC-03 记住与取消关注

玩家可对已经接触的人物通过界面明确设置“记住”或取消关注。2026-11-11 用户明确允许弹窗，不要求自然语言识别：人物面板提供入口，弹窗确认记住或暂不记住。人物自己说“记住我”不能代替玩家选择。

该操作必须沿用原身份、经历和设定，改变关注状态本身不调用模型、不补全人生、不自动接受任何任务。关注操作直接指定人物，不进行自然语言识别或额外推理。被记住的人物不要求每轮都出场或持续计算。

#### IC-04 逐步丰富而不重造

新增姓名、背景、习惯等只补充相应内容，保留此前有效资料。玩家明确创作补充与 AI 合理创作均需能回查来源。单次冷淡、帮助或拒绝先作为事件，不能自动固化为永久性格。

人物自己说出的信息、他人转述、主观判断与已确立设定分别保存。“我来自北境”首先是一次自述；人物可以隐瞒或撒谎。AI 对尚未定义部分的创作一旦正式成立，后续必须遵守，不能因为玩家尚未获知就反复重写。

与既有内容冲突时，普通续写不能覆盖。明确的玩家设定修订可更新当前档案并留下修订依据；本次不提供自动改写全部历史、回滚重演或全局剧情修复。会使既有硬条件无法成立的修订应明确报告冲突。

#### IC-05 交往留痕与关系演变

普通人物和独立人物的实际对白都具有明确说话者、对象、时间及接触范围。实际行动通过执行结果形成经历，不从最终文学叙述猜测出另一套事件。

人物的信任、戒备和期待可随交往改变，但能追溯相关经历；不能替玩家产生情感，也不能自动形成双向关系。普通人物的必要关系理解同样应连续，不得在其被关注后从“陌生人”重置。

#### IC-06 约定与未解决事项

已经说出的承诺、拒绝、尚待回应的请求需要区别。约定保存参与者、内容、可确定的时间/地点、来源和当前状态。模型不能把请求直接升级成对方已经承诺，也不能把承诺等同于已执行。

明确到期的约定可以成为既有时间调度的提醒原因；普通人物不因此自动开始后台行动。含糊的“改日”不强行生成具体日期。成功、取消、失约、延期有事件依据；到期没有结果可以保留“待处理/逾期”，不能凭空宣称履行。

#### IC-07 下轮实际使用相关资料

人物参与交往时，当前身份、明确约束、相关关系、未解决事项、近期经历和相关旧经历应进入实际使用的上下文。普通人物也必须覆盖，不能只给出姓名简介。

超过最近聊天窗口后仍能根据身份取回重要历史；被记住人物获得长期维护和检索优先级，不能将全部关注人物每轮塞入上下文。姓名未揭露、私密经历或异地活动不会因建档、关注或摘要而泄露。

#### IC-08 摘要只帮助读取

长交往摘要保留来源和覆盖范围，可重建；不能取代原始事件、明确设定和未完成约定。摘要生成失败不回滚已经完成的游玩，不清空旧资料，不悄悄重新生成角色。资料不足时允许不确定回应，不能补造共同经历。

#### IC-09 一致性、恢复与可检查

同轮身份、档案变化、事件、经历和正文保持一致。未提交回合失败或取消不留下半个人物、虚假记忆或新的关注状态；实际模型调用记录保留。已成功保存的关注操作、交往和后果跨重启不丢失。

能够检查一次回应实际加载了哪些人物/经历、为什么加载、写入了什么，以及模型调用次数和失败原因。调试视角与玩家视角分开，历史验证结果不能代替本功能验证。

### P-4 典型连续过程

1. 玩家用“掌门，你怎么来了（女性）”引入或接回一个人；先判断已有身份与场景，不预定她的回应。
2. 双方开始交往，保留第一轮身份与经历；玩家可以暂不关注。
3. 玩家选择记住她，原身份、经历、状态均连续，关注操作无模型请求。
4. 后续得知姓名或补充设定，同一人物档案增量更新；一次性表现保留为事件。
5. 形成一个真实表达的约定，发生意见分歧或帮助，关系与待办延续。
6. 插入其他人物与地点的交往，离场、重启后返访；她的回应仍受之前具体经历影响。

该过程用于讨论连续性，不规定世界必须有掌门、固定性格、指定台词或剧情结局。当前试玩已预置沈清和时，这句“掌门”首先应命中已有身份，不能把预置人物复用误报为新人物创建验证。

## 1. 当前问题与阶段目标

目前一个 NPC 能收到指定观察，按需读取预置私人记忆，再给出完整回应。它尚不能通过实际行动改变处境、形成新经历，并在之后继续推进自己的生活。

需要解决的体验问题是：人物只在被提问时说话，未必主动推进事务；说过的话可能被误当成已经完成的事情；发生过的互动与失败未必影响后续选择。

本阶段的目标是建立最小连续生活闭环：

> 接触信息 → 基于自身目标作出选择 → 表达或尝试行动 → 得到实际结果 → 形成经历与理解 → 后续继续选择。

玩家应能从实际交往中理解人物想做什么、为何这样做，以及此前互动如何影响后续事情。角色可以拒绝、失误、改变主意或暂时等待，结果保持开放。

## 2. 范围与边界

- 面向整个 NewWorld，讨论六类通用角色能力：感知、回忆、通信、尝试行动、维护私有状态、等待与请求后续机会。
- 围绕独立目标、有限认知、真实后果及跨次互动的延续，验证至少两个角色能够交流并分别作出选择。
- 在场与离屏使用一致的角色行为和经历；区别在于能接触的信息和行动机会。
- 一次角色选择可以组合多项能力，也可以直接回应或等待，不要求固定使用顺序。
- 题材可以改变角色可尝试的内容，不将药材交易、修仙或战斗设为通用角色能力的唯一形式。

[MVP](../NewWorld_PRD.md) 的三个 NPC、两个地点是后续组合体验的内容规模，不限制本阶段通用需求。具体新增功能的角色数、动作范围和成功条件仍逐项讨论。

本阶段不展开完整经济、战斗或成长体系，不增加多世界内容库、插件市场或复杂界面。玩家输入、存档恢复、状态修改和重演保留在全项目需求中，但不列为 NPC 原子能力。

## 3. 六类能力的行为要求

### S1-01 感知

角色能够获得眼前环境、自身状态和实际接触的消息，并根据位置、感官、接触条件及自身能力取得信息。

- 信息应能区分已知、未知和不确定，并保留亲历或转述的来源。
- 未接触的信息不能直接变成角色的准确知识；合理接触后可以获知。
- 主动搜查、施法探测或试探可能耗时、暴露自己或失败，应产生实际结果，不能作为免费全知入口。

### S1-02 回忆

角色能够按当前问题回忆自己的经历、信念与既有计划，为回应或行动提供依据。

- 只读取自身在当前世界中可访问的记忆，不取得别人的秘密或另一世界的经历。
- 没有相关记忆时可以表达不确定、询问或换一种做法，不能补造亲历事实。
- 当前信息足够时可以直接选择，不要求每次回忆。

### S1-03 通信

角色能够向可接触的对象或渠道表达内容，知道表达已经送达、未送达或仍在传递。

- 接收者根据自己的目标和理解自由回应；送达不等于同意，要求不等于对方已经照办。
- 表达可以包括询问、拒绝、许诺或谎言；说过什么与内容是否真实必须区分。
- 未接触消息的人不自动知情，后续转告应形成新的信息接触。

### S1-04 尝试行动

角色能够表达行动意图，在自身能力、资源与实际条件允许的范围内尝试，并获得未受理、条件不足、进行中、完成或失败等结果。

- “想做”“已经尝试”和“实际完成”保持区别，角色不能靠对白宣布成功。
- 涉及他人意愿时，由对方作出选择；争取有限资源不能产生互相冲突的成功结果。
- 长期行动开始后可以仍在进行，也可以失败或被中断，不能默认立即完成。

### S1-05 维护私有状态

角色实际接触的信息和结果能够形成新经历，影响其信念、关系理解、目标及计划，并在以后选择中延续。

- 可以误解、改变看法或放弃计划，但不能凭空新增亲历事实。
- 私人理解只改变自己的认知，不直接改变他人的认知、资源归属或共同历史。
- 私人变化不自动广播；关系与心态不要求统一表示成数值。

### S1-06 等待与请求后续机会

角色能够暂不行动，或表达希望在某个世界时刻、相关事件和条件变化后继续的打算。

- 等待可以结束当前选择；机会出现后再判断，不要求立即解决所有问题。
- 计划不保证指定事件会发生，也不保证他人配合；条件变化或角色改变主意时可以修订。
- 等待本身不立即推进世界时间，也不要求角色不断重复思考维持活动。

## 4. 认知、事实与主体性

| 内容 | 行为边界 |
| --- | --- |
| 经历 | 实际接触的消息与结果，区分亲历、转述及来源。 |
| 信念与关系理解 | 相信、怀疑和推测的内容及对他人的看法，可以错误或改变。 |
| 目标与计划 | 希望达到的状态与后续打算，可因结果、机会和条件变化而修订。 |
| 共同事实 | 实际发生的事件、资源归属和已确认约定，私人理解不能覆盖它。 |

例如“商人说已经交货”可以成为经历；是否真的交货取决于实际结果。私人计划不自动变成对外承诺，承诺也不等于已经履行。

NPC 不能替玩家决定未表达的选择、意愿或内心，也不能替另一 NPC 决定其意愿。世界可以影响人物处境，人物分别选择自己的回应。

世界时间由玩家行动推进，关闭应用后暂停。角色行动在共同世界时间中取得进展，在场与离屏角色不各自推进独立时钟。

## 5. 可观察的阶段验收条件

以下是完整“活起来”闭环的验收基线，不表示全部已经通过。具体新增功能从中选取相关条件，确认明确场景后再开发。

| 验收操作 | 可观察的通过条件 |
| --- | --- |
| 给角色一个与自身目标相关的行动机会，玩家不逐条指挥 | 角色能主动推进事务；条件不足时可合理等待，选择有可理解的依据。 |
| 私下传递信息，再接触未在场角色，随后安排合理转告 | 知情范围随实际接触变化，未接触者不无故准确知情。 |
| 两个角色交流请求、条件或拒绝 | 双方分别选择；送达、接受与履行可区分，不预设合作结局。 |
| 提出行动并改变条件，或先后争取同一有限资源 | 能区分意图、尝试与结果；条件不足和冲突不会变成虚假完成。 |
| 经历帮助、拒绝、成功、失败或约定，再经过其他互动 | 后续回应或行动延续此前经历，并能依据反馈调整理解、目标或计划。 |
| 让角色等待或经历进行中的行动，再提供后续机会 | 角色延续进展重新选择，在场与离屏保持同一条因果链。 |

验收允许不同合理对白与结局，以首次有效输出判断，保留失败；不能挑选重生成结果证明成立。工程测试结果与用户验收分别记录在 [测试文档](TEST_REPORT.md)。
