## 1. 当前问题与阶段目标

目前一个 NPC 能收到指定观察，按需读取预置私人记忆，再给出完整回应。它尚不能通过实际行动改变处境、形成新经历，并在之后继续推进自己的生活。

需要解决的体验问题是：人物只在被提问时说话，未必主动推进事务；说过的话可能被误当成已经完成的事情；发生过的互动与失败未必影响后续选择。

本阶段的目标是建立最小连续生活闭环：

> 接触信息 → 基于自身目标作出选择 → 表达或尝试行动 → 得到实际结果 → 形成经历与理解 → 后续继续选择。

玩家应能从实际交往中理解人物想做什么、为何这样做，以及此前互动如何影响后续事情。角色可以拒绝、失误、改变主意或暂时等待，结果保持开放。

## 2. 范围与边界

- 面向整个 NewWorld，讨论六类通用角色能力：感知、回忆、通信、尝试行动、维护私有状态、等待与请求后续机会。
- 围绕独立目标、有限认知、真实后果及跨次互动的延续，验证至少两个角色能够交流并分别作出选择。
- 在场与离屏使用一致的角色行为和经历；区别在于能接触的信息和行动机会。
- 一次角色选择可以组合多项能力，也可以直接回应或等待，不要求固定使用顺序。
- 题材可以改变角色可尝试的内容，不将药材交易、修仙或战斗设为通用角色能力的唯一形式。

[MVP](../NewWorld_PRD.md) 的三个 NPC、两个地点是后续组合体验的内容规模，不限制本阶段通用需求。具体新增功能的角色数、动作范围和成功条件仍逐项讨论。

本阶段不展开完整经济、战斗或成长体系，不增加多世界内容库、插件市场或复杂界面。玩家输入、存档恢复、状态修改和重演保留在全项目需求中，但不列为 NPC 原子能力。

## 3. 六类能力的行为要求

### S1-01 感知

角色能够获得眼前环境、自身状态和实际接触的消息，并根据位置、感官、接触条件及自身能力取得信息。

- 信息应能区分已知、未知和不确定，并保留亲历或转述的来源。
- 未接触的信息不能直接变成角色的准确知识；合理接触后可以获知。
- 主动搜查、施法探测或试探可能耗时、暴露自己或失败，应产生实际结果，不能作为免费全知入口。

### S1-02 回忆

角色能够按当前问题回忆自己的经历、信念与既有计划，为回应或行动提供依据。

- 只读取自身在当前世界中可访问的记忆，不取得别人的秘密或另一世界的经历。
- 没有相关记忆时可以表达不确定、询问或换一种做法，不能补造亲历事实。
- 当前信息足够时可以直接选择，不要求每次回忆。

### S1-03 通信

角色能够向可接触的对象或渠道表达内容，知道表达已经送达、未送达或仍在传递。

- 接收者根据自己的目标和理解自由回应；送达不等于同意，要求不等于对方已经照办。
- 表达可以包括询问、拒绝、许诺或谎言；说过什么与内容是否真实必须区分。
- 未接触消息的人不自动知情，后续转告应形成新的信息接触。

### S1-04 尝试行动

角色能够表达行动意图，在自身能力、资源与实际条件允许的范围内尝试，并获得未受理、条件不足、进行中、完成或失败等结果。

- “想做”“已经尝试”和“实际完成”保持区别，角色不能靠对白宣布成功。
- 涉及他人意愿时，由对方作出选择；争取有限资源不能产生互相冲突的成功结果。
- 长期行动开始后可以仍在进行，也可以失败或被中断，不能默认立即完成。

### S1-05 维护私有状态

角色实际接触的信息和结果能够形成新经历，影响其信念、关系理解、目标及计划，并在以后选择中延续。

- 可以误解、改变看法或放弃计划，但不能凭空新增亲历事实。
- 私人理解只改变自己的认知，不直接改变他人的认知、资源归属或共同历史。
- 私人变化不自动广播；关系与心态不要求统一表示成数值。

### S1-06 等待与请求后续机会

角色能够暂不行动，或表达希望在某个世界时刻、相关事件和条件变化后继续的打算。

- 等待可以结束当前选择；机会出现后再判断，不要求立即解决所有问题。
- 计划不保证指定事件会发生，也不保证他人配合；条件变化或角色改变主意时可以修订。
- 等待本身不立即推进世界时间，也不要求角色不断重复思考维持活动。

## 4. 认知、事实与主体性

| 内容 | 行为边界 |
| --- | --- |
| 经历 | 实际接触的消息与结果，区分亲历、转述及来源。 |
| 信念与关系理解 | 相信、怀疑和推测的内容及对他人的看法，可以错误或改变。 |
| 目标与计划 | 希望达到的状态与后续打算，可因结果、机会和条件变化而修订。 |
| 共同事实 | 实际发生的事件、资源归属和已确认约定，私人理解不能覆盖它。 |

例如“商人说已经交货”可以成为经历；是否真的交货取决于实际结果。私人计划不自动变成对外承诺，承诺也不等于已经履行。

NPC 不能替玩家决定未表达的选择、意愿或内心，也不能替另一 NPC 决定其意愿。世界可以影响人物处境，人物分别选择自己的回应。

世界时间由玩家行动推进，关闭应用后暂停。角色行动在共同世界时间中取得进展，在场与离屏角色不各自推进独立时钟。

## 5. 可观察的阶段验收条件

以下是完整“活起来”闭环的验收基线，不表示全部已经通过。具体新增功能从中选取相关条件，确认明确场景后再开发。

| 验收操作 | 可观察的通过条件 |
| --- | --- |
| 给角色一个与自身目标相关的行动机会，玩家不逐条指挥 | 角色能主动推进事务；条件不足时可合理等待，选择有可理解的依据。 |
| 私下传递信息，再接触未在场角色，随后安排合理转告 | 知情范围随实际接触变化，未接触者不无故准确知情。 |
| 两个角色交流请求、条件或拒绝 | 双方分别选择；送达、接受与履行可区分，不预设合作结局。 |
| 提出行动并改变条件，或先后争取同一有限资源 | 能区分意图、尝试与结果；条件不足和冲突不会变成虚假完成。 |
| 经历帮助、拒绝、成功、失败或约定，再经过其他互动 | 后续回应或行动延续此前经历，并能依据反馈调整理解、目标或计划。 |
| 让角色等待或经历进行中的行动，再提供后续机会 | 角色延续进展重新选择，在场与离屏保持同一条因果链。 |

验收允许不同合理对白与结局，以首次有效输出判断，保留失败；不能挑选重生成结果证明成立。工程测试结果与用户验收分别记录在 [测试文档](TEST_REPORT.md)。
