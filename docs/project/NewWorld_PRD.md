# NewWorld 产品需求文档

**版本：0.1　日期：2026年10月10日　状态：产品需求草案**

NewWorld 是一个玩家可以自由生活的文字 RP 世界。玩家以自己的身份行动，与有各自目标、关系和生活的 NPC 交往；双方的选择产生持续后果，故事从实际互动中形成。

产品定位、世界时间原则和玩家的世界控制权已经明确。本版将 MVP 范围与验收标准作为首版评审基线，仅描述产品行为和体验，不决定技术架构或实现方案。

## 产品定位

### 产品目标

让玩家通过扮演影响世界，并在持续交往中认识人物、建立关系、经历变化。玩家可以追求修炼、冒险、友谊或日常生活，自己决定投入什么。

世界可以预先设定环境、人物背景、关系和初始处境。NPC 可以有计划、秘密、欲望和相互冲突的利益；他们的计划能够成功、失败、被打断或改变。产品不预定剧情走向或结局。

### 目标玩家

希望进入一个世界，以角色身份自由行动，并与具有连续生活经历的人物长期交往的玩家。玩家拥有自己的世界，也保留额外修改世界的自由。

### 要解决的问题

传统 RP 往往需要反复重新生成，才能筛选出合理、优质且满意的回应。人物的动机、对过去的理解和已经发生的后果可能随生成漂移，使玩家难以通过实际扮演推动事情。

本产品要减少这种负担，让角色行为有原因、经历能够延续、选择产生后果。重新生成仍然可用，但正常游玩应当能够依靠行动、沟通和选择继续推进。

## 核心体验

### 玩家自由生活

玩家是世界中的一个人，能够自由交谈、提出行动、改变打算、离开当前地点。NPC 可以帮助、拒绝、误解或利用玩家，回应应当与自己的立场和处境相关。

产品尊重玩家对自身角色的选择和内心的控制。外部事件可以影响玩家的处境，但系统不擅自决定玩家尚未表达的选择、意愿或情绪。

### NPC 自主生活

NPC 有各自的目标、关系和经历，会主动行动，也会回应其他 NPC。他们能够在玩家不在场时交往、交易、赴约、失约或改变计划。

自主性应当体现在玩家可以感知的行为和变化中。不是每次时间推进都必须出现戏剧事件；有行动机会时，人物应当能够根据自身情况推进生活。

### 选择产生持续后果

帮助、拒绝、承诺、失约、交易等行为能够影响后续关系、行动机会或人物处境。这些影响应当在以后互动中得到延续。

NPC 可以误解或撒谎；实际发生的事情、物品归属和已经确认的约定应保持一致。角色说了什么与事情实际上怎样，需要在体验中能够区分。

### 故事来自交互

NPC 的对白、行动、相互反应和后果就是故事的主要内容。人物可以改变主意，玩家可以介入或退出某条线，产品不要求角色配合预先安排的剧情结局。

意外、冲突、失败和安静生活都可以存在。玩家应当能够理解事情发生的原因，并找到继续参与的方式。

## 世界时间与玩家控制

### 世界时间原则

世界时间由玩家行动推进。关闭应用后，整个世界暂停，不按现实离线时长自动发展。

玩家离开某个地点、旅行、等待或闭关时，其他 NPC 也经历同一段世界时间，并依据各自的条件继续生活。再次相遇时，玩家通过对白、消息和环境变化逐渐了解这段经历。

短暂互动与长期行动应具有合理的时间尺度。具体耗时计算、长行动的中断条件和快进细节保留到后续体验设计。

### 世界主人入口

正常游玩通过角色行动影响世界；额外入口允许玩家修改当前状态和重演，以调整自己的世界。作弊是产品允许的用户控制能力。

MVP 至少支持一次明确的当前状态修改，以及上一轮的重演。用户应能辨识自己正在修改状态还是重新生成互动，操作后能够继续游玩，并延续当前选定的结果。

修改是否影响过往经历、其他人的认知，以及更细的修订方式，属于后续交互设计。

## 核心游玩闭环

1. 玩家接触人物与环境，了解眼前的处境。
2. 玩家通过自然语言交谈或行动，做出自己的选择。
3. NPC 根据自身目标、认知和关系回应，互动产生后果。
4. 玩家离开、等待或进行耗时行动，世界时间推进，其他人物继续生活。
5. 玩家再次接触人物和环境，发现变化，感受到此前选择的影响，并继续参与。

首版必须跑通这个闭环。单次对白精彩或某个独立功能可用，不能替代完整体验。

## MVP 范围

### 首版内容规模

首版提供一份可直接游玩的初始小世界：三个 NPC、两个可往返地点、少量可交互物品。

三个 NPC 具有不同目标、彼此关系和可以影响选择的个人经历。世界提供产生互动的条件，后续发展保持开放。首版可以使用修仙背景，具体人物和地点名称尚未确定。

### 必须具备的能力

| 能力 | MVP 要求 |
| --- | --- |
| 自由扮演 | 玩家通过自然语言交谈、提出行动、帮助或拒绝他人，能够改变计划。 |
| 独立人物 | 三个 NPC 有各自目标、关系和记忆，表现有区别，能够主动行动并相互影响。 |
| 基础行动 | 支持交谈、在两个地点间移动、等待，以及简单的物品交互。 |
| 世界推进 | 玩家行动推进时间；不在玩家视野中的人物也能够延续自己的生活。 |
| 持续后果 | 延续位置、物品归属、关系、约定和关键经历，并影响后续互动。 |
| 有限认知 | NPC 依据自己知道或相信的内容行动，秘密通过合理接触或交流被得知。 |
| 连续游玩 | 支持存档和恢复；关闭应用后暂停，重新打开后继续当前世界。 |
| 玩家控制 | 提供独立于正常扮演的当前状态修改和上一轮重演入口。 |

### 首版边界

修炼、冒险、交朋友是长期生活方向。MVP 先通过耗时行动、地点探索、交往和简单物品互动验证核心体验，不承诺完整的修炼成长、战斗、经济或任务体系。

自由创生、角色卡制作平台、多世界内容库、插件市场、多人共享世界、离线持续运行以及复杂 UI 均不纳入本次 MVP。

### 验证世界示例

药师需要药材，采药人急需钱，商人希望收购药材。三人认识彼此，并拥有不同打算；两个地点可以是集市和郊外。

玩家可以帮助其中一人、尝试交易、结交朋友，也可以离开并等待。三人能够依据自己的目的继续行动。示例只规定初始条件，不规定谁必须合作、谁必须欺骗或最终由谁获利。

## 验收标准

### 验收原则

验收围绕可观察的玩家体验展开。故事具体内容可以不同，但人物连续性、共同事实和用户控制权必须满足要求。

核心体验验收默认使用首次有效输出，不以反复重 roll 后挑选满意结果证明通过。失败的回应和后果应保留为问题样本。重演能力另外单独验收。

### 核心验收场景

| 场景 | 验收操作 | 通过标准 |
| --- | --- | --- |
| 自由行动与玩家控制 | 自然语言提出帮助、拒绝或离开的行动，中途改变打算。 | NPC 和世界能理解并回应；玩家可以继续行动，不被固定剧情锁住；系统不擅自决定玩家的意愿或内心。 |
| 人物差异 | 围绕同一资源或请求，分别与三个 NPC 交谈。 | 三人的回应能对应各自目标、关系和处境；差异体现于选择与态度，不能只靠名字和口头禅区分。 |
| 自主行动与 NPC 交往 | 在具有行动机会的初始处境中，玩家离开并推进足够的世界时间，再返回。 | 至少一名 NPC 推进自身目标，且发生一次 NPC 之间的互动；变化可由后续接触感知，并能够说明原因。 |
| 选择的持续后果 | 玩家帮助或拒绝某人，经过其他互动和时间推进后再次见面。 | 至少一处后续回应、关系或行动明确延续此前选择，不能只在当轮给出一句反馈。 |
| 记忆与约定 | 建立一个明确约定，经历其他互动，再询问或履行约定。 | 相关 NPC 能延续约定和关键经历；不能凭空改写已确认的事实。 |
| 认知边界 | 玩家与一名 NPC 私下交流，随后接触未在场的 NPC；再安排合理的消息传递。 | 未接触消息的人不会无故准确知道秘密；消息传递后，知情状态能够在互动中合理体现。 |
| 共同事实 | 两名角色先后争取同一件有限物品，之后核对结果。 | 物品实际归属保持一致；承诺、谎言和真实交付可区分，不出现互相冲突的成功结果。 |
| 时间与离屏变化 | 玩家移动或等待推进时间，之后存档、关闭并重新打开。 | 时间推进与行动相符；离屏人物经历相应时间；恢复后不会增加现实离线期间的世界时间或事件。 |
| 状态修改与重演 | 使用额外入口修改当前状态，再重演上一轮并继续交谈。 | 两种操作能够区分，用户可以选择继续使用的结果；后续互动延续当前状态，旧结果不会与新结果相互冲突。 |

### 完整试玩验收

完成一次自然试玩：认识三人、做出一个选择、离开并推进时间、返回发现变化、再次互动。

体验评审需要能回答以下问题：

- 三个人分别想做什么，玩家是否能从实际交往中理解？
- 是否发生过与 NPC 自身目标有关的主动行为？
- 玩家是否能指出一次自己的选择影响了后续事情？
- 玩家是否能主要通过扮演继续推进，而不依赖反复重 roll 修复不合理内容？
- 重逢和后续互动是否让玩家产生继续参与的意愿？

MVP 通过需要核心场景满足通过标准，并完成上述试玩闭环。继续参与的意愿属于体验反馈，应与具体行为问题一起记录，不作为唯一判断依据。

## 后续决策与范围管理

以下问题已经出现，但本版不增加对应功能要求：

- 长期行动何时可以被打断，是否提供免打扰选择。
- 不同行动的精确耗时、闭关与旅行的快进方式。
- 状态修改如何影响过去的经历和其他 NPC 的认知。
- 首版人物、地点和物品的具体内容，以及修炼和冒险后续扩展的先后顺序。
- 可接受的等待时长、表现方式和细粒度体验指标。

发现新需求时，先判断它是否直接影响自由扮演、NPC 自主生活、选择的持续后果或完整试玩闭环。与这些目标无直接关系的需求进入后续清单，不自动扩大 MVP。

首版评审先核对产品范围和玩家体验。技术选型、架构设计、模块划分和代码实现另行开展。
