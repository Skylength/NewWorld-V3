# 世界与动态区域 PRD

更新：2026-11-06。本文按 `feat/director-core` 当前工作树整理现有功能需求与实现对照；具体技术事实见 [现行框架与世界区域架构](ARCHITECTURE.md)。源码中存在不等于本次已完成真实试玩或用户验收，实际证据保留在 [TEST_REPORT.md](TEST_REPORT.md)。

## 1. 当前范围与状态

现有产品入口是本地文字RP游玩及调试页。支持自然语言行动与交谈、逐步展开未知区域、保存地点变化、地图返访、人物创建与独立回应、时间推进和存档。世界与NPC共用状态，不是两套相互复制的世界。

当前工作树的试玩开局是青云宗前庭、女性掌门沈清和；玩家前来拜师，尚未入门。掌门预先启用独立能力，初始化不请求模型。opening背景长期展示，已融入背景的初始化事件不重复显示。旧存档保留原状态，不被新预设覆盖。

“游玩中人物形成与长期交往”是另一个待审阅增量，主需求见 [NPC PRD](../stage1/PRD.md#游玩中人物形成与长期交往-v01)。关注、渐进档案、约定对象、长期摘要等尚未实现；本次不把这些新设计写成当前交付。

## 2. 核心概念

| 概念 | 当前含义 |
| --- | --- |
| 世界 | 同一存档中的背景、区域、时间、玩家位置、回合与NPC状态 |
| 区域 | 有稳定ID的场所，包含简介、细节、当前状态、互动线索及父区域 |
| 地图 | 区域包含关系的展示和已有地点迁移入口，不代表道路网络 |
| Director | 按玩家输入提出场景、区域、人物及可感知变化 |
| 独立NPC | 根据自身信息选择对白和行动；与普通背景人物区分 |
| 世界时间 | 玩家行动、等待推进的累计分钟，与现实生成/阅读时间分开 |
| 运行记录 | 请求、上下文、提案与错误证据，不等于已经发生的世界事件 |

## 3. 行为要求与当前承载

### W-01 世界与位置背景

当前实际位置由playerLocationId确定；上下文加载区域不代表玩家移动。世界core持续加载，当前位置及其祖先提供背景。明确提及其他地点时可加入相关资料，不能据此把玩家或NPC置于该处。

当前NPC上下文没有直接加载世界core，区域details/state没有字段级秘密权限。世界主人的调试资料与玩家可见信息不能混为一谈。

### W-02 未知区域的按需展开

玩家可以用自然语言前往未知地方，不要求先选择“探索”模式。模型应按已有背景和玩家授权生成具体、可理解的内容；未知不是禁止行动的理由，也不意味着必须奖励、制造冲突或无限生成通道。

已有地点优先复用，新增场所保存稳定ID与合理包含关系。只在形成独立环境或交互条件时建立区域，不给每一步普通移动都建节点。地点的初次细节和后续补充可以逐步展开。

程序检查图结构、引用、名称冲突和容量；具体内容质量、授权理解及合理空间关系仍需要模型与人工试玩验证。

### W-03 自由行动与推进尺度

interact目前是自由行动：明确进入、前往、跟随等可改变位置；单纯提及、打听、回忆、假设和否定前往应保持原位。此语义依赖提示词理解，不能表述为程序已证明每次判断正确。explore是可选快捷提示，沿用同一执行链。

行动跨度按玩家意图和实际选择决定：普通过程可以概括，具体问答可以简短；遇到新的重要风险或决定应交回控制权。不得代写玩家未表达的意愿、对白和内心。界外反馈不应被当作角色动作或耗时，这也是模型行为约束。

复杂的多时刻行动当前需分段；没有任意时间轴、多段旅行中途相遇或精细在途感知系统。

### W-04 持久变化与返访

场景里已成立且影响后续互动的内容应进入档案，不能只留在正文。稳定细节进入details，变化条件进入state；状态值覆盖旧值，null只删除不适用字段。打开的门应保存为“打开”，不是删除门锁状态后让其重新生成。

离开再返回应保留地点、标记、设施状态与已发生后果；旧线索不应覆盖更新后的状态。程序保证按同一ID更新，语言层是否忠实延续仍需验证。现有目录帮助识别旧地点，但没有通用语义别称索引。

### W-05 地图迁移

地图只允许选择已有非当前目的地，并带worldId/baseRevision防止陈旧地图操作。目标由宿主固定，模型不能换地点；地图迁移不得创建或丰富区域。

普通输入不受地图的固定目的地限制。地图仍调用Director与最终叙述，NPC活动和抵达反应按需执行，不是无模型瞬移。地图的父子连线仅投影包含关系。

### W-06 人物交谈与世界联动

主输入向当前在场人物说的话应先投递，再推进本轮时间；独立人物自己回应，Director和最终叙述不应代替其承诺、拒绝或行动。程序检查目标在场和玩家台词来源子串，语义上的“是否说出口”仍由模型判断。

新人物通过createNpcs保存完整seed，默认普通人物；当前实现统一在本轮时间推进后建立，并投递剩余交谈/观察。普通人物对白可进入Director观察文本，尚无完整的逐人档案更新或具名普通对白协议。

玩家抵达给实际同地人物形成观察，人物可以按自身选择接触玩家。主聊天涉及人物时可能发生多个模型请求；不能继续使用“每次行动固定最多两次”的旧说明。

### W-07 时间、失败与继续

世界时间随行动耗时和等待推进，阅读、轮询、关闭服务不推进；加载恢复不补算离线。

主聊天/地图的结构、NPC推演、正文都成功后统一提交；失败/取消保留原世界与实际调用记录，不产生半轮人物或经历。人物面板直接交谈/等待采用另一种检查点保存政策，已完成部分保留、剩余推进暂停；用户可以继续或停止。

暂停推进时先处理continue/stop，再接受新的世界行动。预算不够时应明确显示进度，不能为了完成而隐藏追加调用。当前达到目标但仍有pending也可能显示暂停，是已知限制。

### W-08 可检查的运行过程

调试页展示实际结构/文本请求、NPC关联运行、耗时、usage、上下文组成、候选与已提交变化、原始协议及错误。提示词差异来自历史同阶段实际请求；当前上下文预览不是历史请求的重建。

当前人物私密数据可经本机调试和导出查看；npcView仅是玩家投影，不代表完整HTTP服务具有多人权限隔离。

## 4. 当前页面和存档

统一聊天页用于行动与正文，地图、场景、人物、日志按需查看。人物面板已有创建、设为重要人物、交谈和游戏时间推进；“设为重要人物”目前调用promote，尚无“记住/取消关注”的独立业务状态。背包/技能没有完整玩法。

运行中约800ms、空闲约3000ms轮询，刷新不调用模型。发送后显示运行状态，失败保留可继续输入的草稿；原始失败记录不自动重新请求。开局、回合正文和玩家可见NPC事件根据时间/事件顺序合并，已被正文引用的事件不重复展示。

每个世界自动保存独立JSON，支持列举、加载和导出；新建保留旧世界。仅支持本机单写入者，不能同时用两个服务写同一存档目录。运行版本、配置和历史证据见技术文档与报告，不凭页面端口推断当前服务已更新。

## 5. 当前边界

| 已有 | 仍有限或尚未实现 |
| --- | --- |
| 区域创建/补充、状态更新、祖先上下文与地图返访 | 道路/距离、精细旅行、任意规模地图摘要 |
| Director、普通人物、独立NPC联动 | 所有自然语言的语义校验与任意复杂多人物时序 |
| 自有经历、计划、通信、单向关系 | 长期记忆摘要、明确承诺实体、关注、人物档案增量 |
| 两种提交路径、版本检查及人物命令回执 | 主输入幂等、可恢复候选回合、多进程事务 |
| 单机调试与完整导出 | 多用户访问控制、云托管和并行世界服务 |

世界阶段完整请求最多24000字符，提交前检查下一轮必要上下文不超过20000；全部目录随世界增长，超限会拒绝新增回合，不会自动摘要。人物数最多100、独立人物最多12。预算细则以技术架构为主，不将有限容量表述为无限世界。

## 6. 验收条件与证据解释

| 编号 | 可观察要求 | 当前核对方式 |
| --- | --- | --- |
| A-01 | 从少量背景自然进入未知场所，具体回应玩家探索 | 真实模型试玩；不能只检查新节点存在 |
| A-02 | 当前区域及祖先正确装载，相关异地资料不表示在场 | 实际上下文与正式位置 |
| A-03 | 单纯询问不移动，明确移动按输入推进 | 首次模型输出与存档；语义不靠类型检查证明 |
| A-04 | 改变环境后离开返访，旧后果保留 | 区域ID、state、正文一致 |
| A-05 | 地图目标固定，旧地点不被地图操作重建 | 版本/协议校验与实际请求 |
| A-06 | 在场交谈及时投递，独立人物选择得到尊重 | 玩家输入、NPC事件和最终正文对照 |
| A-07 | 主回合失败/取消无候选事实残留 | 正式世界与失败run记录 |
| A-08 | 人物面板失败保留已完成进度，继续不重做已执行步骤 | 检查点、计划/信件状态与事件 |
| A-09 | 重启身份、地点、状态和进度连续 | 保存/恢复记录；现实时间不补算 |
| A-10 | 能检查模型实际看到的材料和发生的调用 | 请求日志、上下文、差异和usage |
| A-11 | 容量与预算不足可辨认，已有档案不被静默截断 | 错误、正式快照及可继续操作状态 |

本表整理现行能力的验收目标，不新增测试场景文件、不宣称本次全部通过。历史Director联合验证、地图/自由行动问题、最初失败和修订记录均保留在[报告](TEST_REPORT.md)；旧自动测试命令和CI仅代表历史。本轮只核对代码与文档。

## 7. 待审阅增量的联动边界

人物形成增量将来需要轻量身份、增量档案、关注和来源化记忆，主记录为[NPC PRD](../stage1/PRD.md#游玩中人物形成与长期交往-v01)与[技术方案](../stage1/ARCHITECTURE.md#游玩中人物形成与长期交往-v01)。其中拟议的start/arrival人物出现顺序、characterDelta、track、事项和摘要均未实现。

该增量优先游玩中的人物形成，不扩展开局创建。当前预置掌门仍需先复用；不能把与既有沈清和交谈误报为动态新人物验证。已有试玩初始化和历史验收记录不因新方案被覆盖。
